# نوا — پلتفرم گفتگوی لحظه‌ای فارسی

پیام‌رسان گروهی به سبک دیسکورد با سرور، کانال متنی/صوتی، نقش و مجوز، پیام مستقیم، دوستان و تماس صوتی/تصویری.
**بدون هیچ مرحلهٔ build یا کامپایل**: Node.js 20 + Express + Socket.IO + PostgreSQL، و فرانت‌اند HTML/CSS/JS ساده.

> نام محصول فقط در یک جا تعریف شده: ثابت `APP_NAME` در فایل `config.js`.

## استقرار روی Railway
1. محتویات این zip را **مستقیم در ریشهٔ مخزن** `email1fje-dev/irandiscord` قرار دهید (بدون پوشهٔ اضافه) و commit کنید.
2. در Railway: **New Project → Deploy from GitHub repo** و مخزن را انتخاب کنید.
3. **+ New → Database → Add PostgreSQL** را بزنید. سپس در سرویس برنامه، در **Variables**، متغیر `DATABASE_URL` را با گزینهٔ *Add Reference* به همان دیتابیس وصل کنید.
4. متغیر `JWT_SECRET` را با یک رشتهٔ تصادفی بلند بسازید.
5. (اختیاری ولی توصیه‌شده) یک **Volume** بسازید، آن را روی مسیر `/data` به سرویس وصل کنید و `UPLOAD_DIR=/data/uploads` را تنظیم کنید؛ وگرنه فایل‌های آپلودشده با هر استقرار پاک می‌شوند.
6. در **Settings → Networking → Generate Domain** دامنه بسازید. مسیر سلامت: `/health`.

جدول‌های دیتابیس هنگام اجرا خودکار ساخته می‌شوند؛ هیچ دستور اضافه‌ای لازم نیست.

## متغیرهای محیطی
| متغیر | الزامی | توضیح |
|---|---|---|
| `DATABASE_URL` | بله | آدرس PostgreSQL |
| `ADMIN_PASSWORD` | توصیه‌شده | گذرواژهٔ حساب مدیر Nava (اگر نباشد تصادفی ساخته و یک‌بار در لاگ چاپ می‌شود) |
| `JWT_SECRET` | توصیه‌شده | کلید امضای نشست؛ اگر نباشد کلید تصادفی ساخته می‌شود (با هر ری‌استارت همه خارج می‌شوند) و هشدار چاپ می‌شود |
| `PORT` | خیر | Railway خودش تنظیم می‌کند؛ سرور روی `0.0.0.0` گوش می‌دهد |
| `UPLOAD_DIR` | خیر | مسیر فایل‌های آپلودی (پیش‌فرض `./uploads`) |
| `PGSSL` | خیر | اگر دیتابیس SSL می‌خواهد `true` بگذارید |
| `TURN_URL` / `TURN_USERNAME` / `TURN_CREDENTIAL` | خیر | سرور TURN برای تماس صوتی/تصویری پشت NATهای سخت |

## حساب مدیر «Nava» و پنل مدیریت
هنگام اولین اجرا، حساب مدیر با نام کاربری **Nava** و **تیک آبی** خودکار ساخته می‌شود (ورود با `nava` یا `Nava` فرقی ندارد).
- اگر متغیر `ADMIN_PASSWORD` را تنظیم کرده باشید، همان گذرواژه است (و با هر بار اجرا دوباره اعمال می‌شود؛ برای ریست گذرواژه کافی است آن را عوض کنید).
- اگر تنظیم نکرده باشید، یک گذرواژهٔ تصادفی ساخته و **فقط یک‌بار در لاگ‌های Railway** چاپ می‌شود (دنبال خطی با `[admin] Generated password` بگردید). بعد از ورود آن را از تنظیمات تغییر دهید.
- حساب Nava محافظت‌شده است: مسدود، حذف یا بی‌تیک نمی‌شود و فقط خودش می‌تواند به دیگران دسترسی مدیریت بدهد.

پنل: تنظیمات (⚙) → «پنل مدیریت سایت». امکانات (۱۵ مورد):
1. آمار کلی (کاربر، آنلاین، سرور، کانال، پیام، پیام ۲۴ ساعت، عضو جدید ۷ روز…)
2. فهرست و جستجوی کاربران
3. مسدود / رفع مسدودی کاربر
4. **دادن / برداشتن تیک آبی کاربر**
5. **دادن / برداشتن تیک آبی سرور**
6. حذف سرور
7. ریست گذرواژهٔ کاربر
8. خروج اجباری کاربر از همهٔ دستگاه‌ها
9. ویرایش نام نمایشی و پاک کردن متن وضعیت
10. حذف همهٔ پیام‌های یک کاربر
11. حذف حساب کاربر (و سرورهای او)
12. دادن / گرفتن دسترسی مدیریت (فقط Nava)
13. فهرست کاربران آنلاین
14. اطلاعیهٔ سراسری (زنده برای آنلاین‌ها، و یک‌بار برای بقیه در ورود بعدی)
15. باز/بستن ثبت‌نام + گزارش (audit log) همهٔ اقدام‌های مدیران

تیک آبی کنار نام در پیام‌ها، فهرست اعضا، دوستان، پیام مستقیم، پروفایل و نام سرور نمایش داده می‌شود.

## انیمیشن‌ها
باز و بسته شدن نرم مودال‌ها و منوها، ورود پیام‌های جدید، اعلان‌ها (toast)، گذار بین صفحه‌ها روی گوشی، واکنش‌ها و شمارنده‌ها، حلقهٔ گفتار در تماس صوتی و افکت آیکون سرورها. همه فقط CSS هستند و اگر در دستگاه «کاهش حرکت» روشن باشد خودکار خاموش می‌شوند.

## فونت وزیرمتن
چون فایل فونت داخل zip نیست، سرور هنگام اولین اجرا آن را یک‌بار دانلود و در `public/fonts` ذخیره می‌کند و از همان‌جا (محلی) ارائه می‌دهد؛ مرورگر هیچ درخواست فونت بیرونی نمی‌زند. اگر دانلود ممکن نشد از فونت سیستم استفاده می‌شود. برای قرار دادن دستی فایل‌ها به `public/fonts/README.txt` نگاه کنید.
